# `final-review.ts` 를 없애고 그 내용을 제자리에 옮기기

> **휙휙 패스보다 먼저 한다.** 휙휙 패스가 대표 그림을 다시 만드는데,
> 이걸 안 고치고 그림을 다시 만들면 프랑스말 그림 하나가 화면과 달라진다.

## 무엇이 문제인가

`src/i18n/final-review.ts` 가 **다른 파일에 적힌 값을 실행 중에 덮어쓴다.**
`BaseLayout.astro` 가 그 파일을 불러오면서 네 가지가 바뀐다.

| 어디 | 원래 파일에 적힌 것 | 덮어쓴 것 |
|---|---|---|
| `games.ts` 프랑스말 몽글 과일 | `Fruits Fusion` | `Fusion Fruitée` |
| `hoppy-jump` 일본말 발문 | 옛 문장 | `足場を跳びついで、どこまで高く行ける？` |
| `privacy.ts` 「사이트 파일은 어디서 오나요」 | 옛 문장 | 비콘을 밝힌 새 문장 |
| `privacy.ts` 「어린이」 | 옛 문장 | 기술 정보 처리를 밝힌 새 문장 |

**글 내용은 다 맞다. 고칠 것은 방식뿐이다.**

### 왜 지금 고쳐야 하나 — 재 봤다

```
games.ts 에 적힌 프랑스말 이름   →  Fruits Fusion
화면에 나오는 이름               →  Fusion Fruitée   (덮어쓰기가 이긴다)
대표 그림 만드는 곳이 읽는 이름  →  Fruits Fusion    (덮어쓰기를 안 거친다)
```

`scripts/og-data.ts` 는 `src/data/games.ts` 를 그대로 읽고 `final-review` 를 안 거친다.
그래서 **`node scripts/make-og.mjs` 를 다시 돌리는 순간** 프랑스말 몽글 과일 대표 그림만
화면과 다른 이름이 된다. 지금 그림은 덮어쓰기 전에 만든 것이라 우연히 맞는 상태다.

### 하나 더 — 몇 번째 칸인지로 집는다

```js
copy.blocks[6] = …   // 「사이트 파일은 어디서 오나요」
copy.blocks[7] = …   // 「어린이」
```

개인정보 쪽에 덩어리를 하나만 끼워 넣어도 **엉뚱한 칸이 조용히 바뀐다.**
하필 개인정보 쪽에서 그러면 안 된다.

---

## 손댈 파일

1. `src/data/games.ts` — 프랑스말 이름 한 줄
2. `src/games/hoppy-jump/strings.ts` — 일본말 발문 한 줄
3. `src/text/privacy.ts` — 덩어리 두 개 × 나라말 여섯 개
4. `src/layouts/BaseLayout.astro` — 가져오기 한 줄 지우기
5. `src/i18n/final-review.ts` — **파일을 지운다**

---

## 1. `src/data/games.ts`

`merge-fruit` 칸의 프랑스말 이름을 바꾼다.

```ts
      fr: ['Fruits', 'Fusion'],
```

아래로.

```ts
      fr: ['Fusion', 'Fruitée'],
```

---

## 2. `src/games/hoppy-jump/strings.ts`

일본말(`ja`) 덩어리의 `tagline` 을 아래로 바꾼다.

```ts
    tagline: '足場を跳びついで、どこまで高く行ける？',
```

---

## 3. `src/text/privacy.ts`

**`final-review.ts` 에 있는 글을 그대로 옮겨 적는다.** 새로 쓰지 않는다.
한 글자도 바꾸지 말고 복사한다.

나라말 여섯 개 각각에서 **덩어리 두 개**를 찾아 `p` 배열을 통째로 갈아 끼운다.

- `final-review.ts` 의 `files` → 「사이트 파일은 어디서 오나요」 덩어리
  (en `Where the files come from` · ja `ファイルはどこから来るか` ·
   es `De dónde vienen los archivos` · fr `D’où viennent les fichiers` · zh `文件从哪里来`)
- `final-review.ts` 의 `children` → 「어린이」 덩어리
  (en `Children` · ja `子ども` · es `Menores` · fr `Enfants` · zh `儿童`)

**몇 번째 칸인지로 찾지 말고 머리말로 찾는다.** 그게 이번에 고치는 이유다.

`h`(머리말)는 그대로 둔다. `p` 배열만 바꾼다.

---

## 4. `src/layouts/BaseLayout.astro`

이 줄을 **지운다.**

```ts
import '../i18n/final-review';
```

---

## 5. `src/i18n/final-review.ts`

**파일을 지운다.** 옮겨 적고 나면 쓰는 데가 없다.

---

## 6. 대표 그림 다시 만들기

프랑스말 이름이 `games.ts` 에서 바뀌었으니 그림도 다시 만든다.

```bash
node scripts/make-og.mjs
```

---

## 하지 말 것

- **글을 새로 쓰지 않는다.** `final-review.ts` 에 있는 것을 그대로 옮긴다
- 개인정보 쪽의 다른 덩어리를 건드리지 않는다
- 머리말(`h`)을 바꾸지 않는다
- `TEXT_UPDATED` 를 건드리지 않는다. **글 내용이 안 바뀌기 때문이다** —
  자리만 옮기는 것이라 날짜를 올리면 거짓말이 된다
- 게임·대문·읽는 쪽 짜임을 건드리지 않는다

---

## 끝났다는 신호

- `final-review.ts` 가 없고, 어디서도 안 부른다
- 화면에 나오는 글이 **하나도 안 바뀐다.** 자리만 옮긴 것이라 그래야 맞다
- 프랑스말 몽글 과일 대표 그림이 화면 제목과 같아진다

---

## 확인 차례

```bash
npm run build
```

**덮어쓰기가 정말 없어졌는지 센다.**

```bash
grep -rn "final-review" src/ | wc -l          # 0
```

**화면과 대표 그림이 같은 이름을 쓰는지 센다.**

```bash
grep -o "<title>[^<]*</title>" dist/fr/play/merge-fruit/index.html
# → Fusion Fruitée — Jeu en ligne gratuit | Hanveon

npx esbuild scripts/og-data.ts --bundle --format=esm --outfile=/tmp/ogd.mjs \
&& node -e 'import("/tmp/ogd.mjs").then(m=>{const g=m.GAMES.find(x=>x.slug==="merge-fruit");console.log(m.fullName(g,"fr"))})'
# → Fusion Fruitée
```

**개인정보 쪽 글이 안 바뀌었는지 센다.** 고치기 전에 미리 받아 두고 뒤와 견준다.

```bash
# 고치기 전에
npm run build && cp -r dist /tmp/before
# 고친 뒤에
npm run build && diff -r /tmp/before/ko/legal/privacy dist/ko/legal/privacy && echo "한국말 개인정보 쪽 그대로"
```

- [ ] `grep` 결과가 `0`
- [ ] 두 이름이 둘 다 `Fusion Fruitée`
- [ ] 개인정보 쪽 여섯 나라말이 **글자 하나 안 바뀜**
- [ ] 일본말 폴짝 점프 발문이 그대로 `足場を跳びついで、どこまで高く行ける？`
- [ ] 대표 그림 48장, 프랑스말 몽글 과일 그림을 눈으로 열어 이름 확인
- [ ] 콘솔에 오류가 없다
