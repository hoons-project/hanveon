# 단계 6 — 소개·연락·개인정보·쿠키·약관·404 쪽 붙이기

> **글은 이미 다 들어와 있다.** `src/text/` 를 열어 보면 여섯 나라말 글이 그대로 있다.
> 이 지시서는 **그 글을 화면에 붙이는 일**만 다룬다. 글은 한 글자도 안 고친다.

## 목표

읽는 쪽 다섯을 만든다. 나라말마다 주소가 따로 있다.

| 주소 (영어) | 무엇 | 날짜 줄 |
|---|---|---|
| `/about/` | 소개 | 없음 |
| `/contact/` | 연락 | 없음 |
| `/legal/privacy/` | 개인정보 | **있음** |
| `/legal/cookies/` | 쿠키 | **있음** |
| `/legal/terms/` | 이용 약관 | **있음** |

한국말이면 `/ko/about/` `/ko/legal/privacy/` 꼴이다. **영어만 앞자리가 안 붙는다** —
이미 있는 규칙 그대로다.

그리고 없는 주소로 갔을 때 나오는 **404 쪽**을 나라말마다 하나씩 만든다.

발쪽과 햄버거 목차에 이 다섯으로 가는 링크를 넣는다.

### 왜 지금 하나

애드센스는 개인정보·연락 쪽이 없으면 안 받아준다. 그것 말고도, **로봇이 읽을 글**이
이 사이트에 너무 적다. 지금은 게임 쪽 읽을 글이 전부다. 소개 쪽 하나가 그것을 크게 채운다.

## 1. `src/i18n/index.ts`

### 1-1. 갈래에 이름을 붙인다

`isLang` **위**에 넣는다.

```ts
/** 쪽의 갈래. 대표 그림과 hreflang 을 만드는 데 쓴다. */
export type PageKind = 'home' | 'game' | 'text';

/**
 * 읽는 쪽 주소. 영어는 `/about/`, 나머지는 `/ko/about/`.
 * `slug` 는 `about` `legal/privacy` 처럼 앞뒤 빗금 없이 준다.
 */
export function textPath(lang: Lang, slug: string): string {
  return lang === BASE_LANG ? `/${slug}/` : `/${lang}/${slug}/`;
}
```

### 1-2. `ogPath` 를 갈아 끼운다

```ts
/**
 * 대표 그림 주소. 카톡·트위터에 링크를 붙일 때 나오는 1200×630 그림이다.
 * 그림은 `scripts/make-og.mjs` 가 `public/og/` 에 만들어 둔다.
 *
 * **읽는 쪽은 대문 그림을 같이 쓴다.** 쪽마다 그림을 새로 만들지 않는다 —
 * 지금도 42장인데 30장이 더 늘고, 글만 있는 쪽에 그림을 따로 줄 이유가 없다.
 */
export function ogPath(kind: PageKind, lang: Lang, slug?: string): string {
  return kind === 'game' ? `/og/${slug}-${lang}.png` : `/og/home-${lang}.png`;
}
```

### 1-3. `altPaths` 를 갈아 끼운다

```ts
/**
 * 같은 페이지의 여섯 나라말 주소를 다 만든다.
 * `hreflang` 을 넣을 때 쓴다.
 */
export function altPaths(kind: PageKind, slug?: string): { lang: Lang; path: string }[] {
  return LANGS.map((lang) => ({
    lang,
    path:
      kind === 'home' ? homePath(lang)
      : kind === 'game' ? gamePath(lang, slug!)
      : textPath(lang, slug!),
  }));
}
```

## 2. `src/layouts/BaseLayout.astro`

### 2-1. 앞머리

`kind` 의 갈래를 넓히고 `noindex` 를 더한다.

```ts
import '@fontsource-variable/inter/wght.css';
import '../styles/global.css';
import { altPaths, HREFLANG, ogPath, type Lang, type PageKind } from '../i18n';
import { ui } from '../i18n/ui';

interface Props {
  lang: Lang;
  /** 이 페이지가 대문인지 게임인지 읽는 쪽인지. hreflang 과 대표 그림을 만드는 데 쓴다. */
  kind: PageKind;
  /** 게임이면 게임 slug, 읽는 쪽이면 `about` `legal/privacy` 같은 것. */
  slug?: string;
  title?: string;
  description?: string;
  /** 검색엔진에 주는 구조화 자료. 그대로 JSON 으로 박힌다. */
  jsonLd?: unknown;
  /** 참이면 검색에 안 걸리게 한다. 404 쪽에만 쓴다. */
  noindex?: boolean;
}

const { lang, kind, slug, title, description, jsonLd, noindex = false } = Astro.props;
const t = ui(lang);

const docTitle = title ?? t.homeTitle;
const desc = description ?? t.metaDesc;

/* 크롤러와 SNS는 상대 주소를 못 푼다. astro.config.mjs 의 site 에서 절대 주소를 만든다. */
const canonical = new URL(Astro.url.pathname, Astro.site);
/* 404 쪽은 주소가 정해져 있지 않다. 나라말 짝을 만들면 거짓말이 된다 */
const alts = noindex ? [] : altPaths(kind, slug);
const ogImage = new URL(ogPath(kind, lang, slug), Astro.site);
```

### 2-2. `<head>` 안 두 군데

지금 이 줄을

```astro
    <link rel="canonical" href={canonical} />
```

아래 둘로 바꾼다.

```astro
    {!noindex && <link rel="canonical" href={canonical} />}
    {noindex && <meta name="robots" content="noindex, follow" />}
```

그리고 x-default 줄을 아래로 바꾼다. **`alts` 가 빌 수 있어서 그냥 두면 빌드가 깨진다.**

```astro
    {alts.length > 0 && (
      <link rel="alternate" hreflang="x-default" href={new URL(alts[0]!.path, Astro.site)} />
    )}
```

다른 것은 그대로 둔다. `alts.map(...)` 은 빈 배열이면 아무것도 안 그린다.

### 8-2. 햄버거가 왼쪽으로 가면서 같이 바뀌는 것

`.topright` 규칙을 아래로 갈아 끼운다. **이름이 바뀐다.**

```css
/* ── 머리 왼쪽 묶음과 햄버거 목차 ─────────────────── */
.topleft{ display:flex;align-items:center;gap:10px }
```

단추가 왼쪽으로 갔으니 판도 왼쪽에 붙어 내려와야 한다.

```css
.menupanel{
  position:absolute;top:calc(100% + 10px);left:0;z-index:20;
  min-width:230px;
  …나머지는 그대로…
}
```

**`.topright` 는 이제 쓰는 데가 없다.** 남겨 두지 않는다.

```astro
import type { TextCopy, TextSlug } from '../../text';

  return ['privacy', 'cookies', 'terms'].map((page) => ({ params: { page } }));
}

const page = Astro.params.page as string;
```

## 9-9. `scripts/split-404.mjs` — 새 파일 (**꼭 필요하다**)

> 이 지시서를 쓴 쪽에서 **실제로 넣고 빌드해 봤다.** 위 `[lang]/404.astro` 만으로는
> **안 된다.** 아래를 같이 넣어야 한다.

무엇이 문제인가 —

`trailingSlash:'always'` 라서 Astro 는 `[lang]/404.astro` 를
**`dist/ko/404/index.html`** 로 내놓는다. 파일 이름이 `404.html` 이 아니다.
Cloudflare 는 `404.html` 이라는 **이름**을 찾으므로 이걸 못 쓴다.
맨 위 `dist/404.html` 만 특별히 그 이름으로 나온다.

그래서 빌드 뒤에 이름을 옮긴다.

```js
// ─────────────────────────────────────────────────────────────
//  나라말별 404 를 제자리로 옮긴다. 빌드 뒤에 저절로 돈다 (`postbuild`).
//
//  왜 필요한가 —
//    Cloudflare Pages 는 없는 주소를 만나면 그 주소에서 **위로 올라가며**
//    제일 가까운 `404.html` 을 찾는다. 그러니까 `/ko/asdf/` 는
//    `/ko/asdf/404.html` → `/ko/404.html` → `/404.html` 차례로 찾는다.
//
//    그런데 Astro 는 `trailingSlash:'always'` 라서 `[lang]/404.astro` 를
//    `dist/ko/404/index.html` 로 내놓는다. **파일 이름이 `404.html` 이 아니라서
//    Cloudflare 가 못 찾는다.** 맨 위 `dist/404.html` 만 특별히 그 이름으로 나온다.
//
//  그래서 여기서 옮긴다 —
//    dist/ko/404/index.html  →  dist/ko/404.html   (그리고 빈 폴더를 지운다)
//
//  폴더를 지우는 이유 — 안 지우면 `/ko/404/` 가 그냥 열리는 진짜 쪽이 된다.
//  없는 쪽을 보여주는 쪽이 자기 주소를 갖는 것은 말이 안 된다.
// ─────────────────────────────────────────────────────────────

import { readFile, writeFile, rm, access } from 'node:fs/promises';
import { join } from 'node:path';

const DIST = 'dist';
const LANGS = ['ko', 'ja', 'es', 'fr', 'zh'];

let moved = 0;

for (const lang of LANGS) {
  const from = join(DIST, lang, '404', 'index.html');
  const to = join(DIST, lang, '404.html');

  try {
    await access(from);
  } catch {
    console.error(`[404] 못 찾음: ${from}`);
    process.exitCode = 1;
    continue;
  }

  await writeFile(to, await readFile(from));
  await rm(join(DIST, lang, '404'), { recursive: true, force: true });
  moved++;
}

console.log(`[404] 나라말 404 ${moved}개를 제자리로 옮겼다`);

if (moved !== LANGS.length) {
  console.error('[404] 개수가 안 맞는다. 빌드를 멈춘다');
  process.exitCode = 1;
}
```

### `package.json` 에 한 줄

```json
"scripts": {
  "dev": "astro dev",
  "build": "astro build",
  "postbuild": "node scripts/split-404.mjs",
  "preview": "astro preview",
  "check": "astro check"
}
```

`postbuild` 는 **npm 이 `build` 뒤에 저절로 돌린다.** Cloudflare Pages 도
`npm run build` 를 쓰므로 배포할 때도 같이 돈다. 꾸러미를 새로 받을 것은 없다.

## 확인 차례

```bash
npm run build
```

마지막에 `[404] 나라말 404 5개를 제자리로 옮겼다` 가 찍혀야 한다.

**쪽이 다 나왔는지 센다.** 아래 숫자는 지시서를 쓴 쪽에서 **실제로 빌드해서 나온 값**이다.

```bash
# 읽는 쪽 30개
find dist -path "*/about/index.html" -o -path "*/contact/index.html" \
     -o -path "*/legal/*/index.html" | wc -l          # 30

# 404 는 나라말마다 하나씩, 모두 6개
find dist -name "404.html" | sort

# 404 폴더가 남아 있으면 안 된다
find dist -type d -name 404 | wc -l                   # 0
```

`404.html` 이 아래 여섯이어야 한다.

```
dist/404.html
dist/es/404.html
dist/fr/404.html
dist/ja/404.html
dist/ko/404.html
dist/zh/404.html
```

**사이트맵을 센다.** 사이트맵은 한 줄로 나와서 `grep -c` 로는 못 센다. `-o` 를 써야 한다.

```bash
grep -o "<url>" dist/sitemap-0.xml | wc -l     # 42 → 72 (읽는 쪽 30개가 늘었다)
grep -o "404"   dist/sitemap-0.xml | wc -l     # 0
```

**404 쪽에 noindex 가 붙었는지, 다른 쪽엔 안 붙었는지 본다.**

```bash
grep -rl "noindex" dist --include="*.html" | sort      # 404.html 여섯 개만
```

- [ ] 위 셈이 각각 `30` · `6개` · `0` · `72` · `0` 인지
- [ ] `noindex` 가 404 여섯 개에만 붙었는지
- [ ] `/ko/legal/privacy/` 의 `<link rel="canonical">` 이 그 주소를 가리키는지
- [ ] `/ko/legal/privacy/` 에 hreflang 이 여섯 + x-default 로 일곱 줄인지
- [ ] `/fr/contact/` 에서 메일 주소가 큰 글씨로 나오고 눌리는지
- [ ] 발쪽 링크가 나라말을 지키는지 — `/ja/about/` 발쪽의 「利用規約」이 `/ja/legal/terms/` 로 가는지
- [ ] 390px 과 320px 에서 발쪽 링크 다섯이 안 넘치고 줄바꿈되는지
- [ ] 햄버거 목차에서 게임 여섯 + 그 밖에 다섯이 줄 하나로 나뉘어 보이는지
- [ ] **햄버거가 왼쪽 위, 로고 바로 앞에 있는지.** 누르면 판이 **왼쪽에 붙어** 내려오는지
- [ ] 목차가 폰(390px·320px)에서 화면 밖으로 안 나가는지 —

- [ ] 콘솔에 오류가 없다
