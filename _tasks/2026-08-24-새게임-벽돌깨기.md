# 새 게임 — 벽돌 깨기 (`brick-breaker`)

## 목표

열한 번째 게임. 공을 튕겨 벽돌을 깨고, 벽돌에서 **아이템이 떨어진다.**
좋은 아이템 넷 · 나쁜 아이템 둘. **판이 12개** 있고 다 깨면 처음으로 돌되 공이 빠른 채로 이어진다.

`design/new-game-checklist.md` 의 아홉 단계를 그대로 따른다. 아래는 그 차례에 채워 넣을 값이다.

## 2. 판 크기와 숫자 — 이 값을 바꾸지 않는다

캔버스 **360 × 620**. 바탕색 `#3B2F3F`.
(다른 게임이 쓰는 `#2F3B4A` `#2B2F55` 와 다른 값이다. 겹치지 않게 이 값을 쓴다.)

### 벽돌 판

| 무엇 | 값 |
|---|---|
| 열 | 7 |
| 최대 줄 | 8 |
| 벽돌 크기 | 폭 44 · 높이 18 |
| 벽돌 사이 | 4 |
| 좌우 여백 | 14 |
| 첫 줄 y | 70 |
| 줄 간격 | 22 |

### 막대와 공

| 무엇 | 값 |
|---|---|
| 막대 기본 폭 | 76 (높이 12, y = 566) |
| 공 반지름 | 6 |
| 공 속도 (판 1) | 4.2 (60프레임 기준 한 프레임에 가는 거리) |
| 판마다 | +0.18 (판 12 = 6.18) |
| 공 속도 최대 | 6.6 |
| 목숨 | 3 |

**튕기는 각도** — 막대 어디에 맞았는지를 `-1`(왼끝) ~ `+1`(오른끝) 로 보고,
튕겨 나가는 각을 **접점 × 60도**로 한다.
단 수직에 너무 가까우면(±15도 안쪽) **±15도로 밀어낸다.** 안 그러면 위아래로만 왕복해서 지루하다.

### 벽돌 두 가지

| 벽돌 | 몇 대 | 점수 |
|---|---|---|
| 보통 | 1 | 10 |
| 단단한 것 | 2 (한 대 맞으면 색이 옅어진다) | 25 |

**안 깨지는 벽돌은 넣지 않는다.** 막판이 지루해진다.

- 판 1~3 — 보통 벽돌만
- 판 4~7 — 단단한 벽돌이 전체의 15% 안팎
- 판 8~12 — 단단한 벽돌이 전체의 30% 안팎

### 점수

- 벽돌 — 보통 10 · 단단 25
- 판 하나 깰 때마다 **+200**
- 판을 깬 시점에 남은 목숨 하나당 **+50**

최고 기록 열쇠말은 **`brickBest`** 다. (`best` 같은 흔한 말을 쓰지 않는다.)

## 3. 아이템 여섯

**벽돌 하나를 깰 때 14% 확률로 하나 떨어진다.**
떨어지는 속도 2.2. 크기 20×20.

무엇이 나올지는 **좋은 것 70% · 나쁜 것 30%** 로 가른 뒤,
좋은 것 넷 중 하나를 고르고(각 17.5%), 나쁜 것 둘 중 하나를 고른다(각 15%).

### 좋은 것 넷 — 둥근 네모(`rx` 6), 바탕 `#7FD8C8`

| 열쇠말 | 무엇 | 얼마나 |
|---|---|---|
| `wide` | 막대가 길어진다 (76 → 112) | 12초 |
| `multi` | 공이 둘 늘어난다 (지금 공에서 ±25도). 화면에 최대 5개 | 계속 |
| `slow` | 공이 느려진다 (×0.72) | 10초 |
| `pierce` | 벽돌을 튕기지 않고 뚫고 지나간다 | 10초 |

### 나쁜 것 둘 — **뾰족한 마름모**, 바탕 `#FF385C`

| 열쇠말 | 무엇 | 얼마나 |
|---|---|---|
| `narrow` | 막대가 짧아진다 (76 → 50) | 10초 |
| `fast` | 공이 빨라진다 (×1.3) | 8초 |

### 겹칠 때 규칙

- 같은 아이템을 또 받으면 **시간이 새로 시작한다.** 효과가 더 세지지는 않는다
- **좋은 것과 나쁜 것은 서로 푼다** —
  `wide` 를 받으면 `narrow` 가 바로 풀리고, 그 반대도 같다. `slow` ↔ `fast` 도 같다.
  이래야 나쁜 아이템이 억울하지 않다

### 색약인 사람도 가릴 수 있어야 한다

**색만으로 좋고 나쁨을 나누지 않는다.**
좋은 것은 **둥근 네모**, 나쁜 것은 **마름모**다. 모양이 다르다.
그 위에 아이템마다 다른 그림을 그린다 —

- `wide` 가로로 긴 막대 · `multi` 작은 동그라미 셋
- `slow` 짧은 아래 화살표 · `pierce` 위로 뚫는 화살표
- `narrow` 가운데로 모이는 화살표 둘 · `fast` 위로 향한 두 겹 화살표

**이 규칙을 `design/README.md` 에도 한 줄 넣는다** —
「캔버스 안에서 좋고 나쁨을 나눌 때 색만 쓰지 않는다. 모양도 다르게 한다.」
지금 그 문서에 이런 규칙이 없다. 다음 게임부터 계속 지켜지게 한다.

## 4. 판 12개

배열로 적는다. `0` 빈칸 · `1` 보통 · `2` 단단.
한 줄이 7칸, 최대 8줄이다.

- **판마다 벽돌은 24~40개** 사이
- 판이 올라갈수록 늘고, 판 12가 제일 많다
- 좌우가 **대칭**이면 보기 좋다

처음 셋은 이렇게 한다.

```
판 1 (28개)          판 2 (30개)          판 3 (33개)
1111111              0111110              1111111
1111111              1111111              1010101
1111111              1111111              1111111
1111111              0111110              1010101
                     1111111              1111111
```

**나머지 아홉 판은 클로드 코드가 만든다.** 만든 뒤 **판마다 벽돌 개수와 단단한 벽돌 비율을
표로 찍어서 알려준다.** 위 조건에 맞는지 눈으로 볼 수 있게.

### 판을 다 깨면

- 판 1~11 — 「판 {n} 깼다」 화면 → 「다음 판」
- 판 12 — 「12판 전부 깼다」 화면 → 「이어서 하기」를 누르면
  **판 1부터 다시 돌되 공 속도는 그대로 이어진다** (6.18에서 시작, 최대 6.6).
  점수와 목숨도 이어진다

---

## 5. 막판이 지루해지지 않게 — 이게 제일 중요하다

벽돌 두세 개 남았을 때 공이 계속 헛도는 것을 막아야 한다.

1. **남은 벽돌이 3개 이하가 되면** 그 판 동안 공 속도 ×1.15
2. 그 상태로 **20초**가 지나면, **5초마다 남은 벽돌이 한 줄씩 아래로 내려온다.**
   최대 3줄까지만 내려온다

내려오면 맞히기 쉬워져서 저절로 끝난다.

## 7. 하지 말 것

- **`Breakout` 과 `Arkanoid` 를 쓰지 않는다.** 각각 아타리와 타이토 상표다.
  `Brick Breaker` · `벽돌 깨기` · `ブロック崩し` · `打砖块` 는 일반 명칭이라 괜찮다
- **안 깨지는 벽돌을 넣지 않는다** (막판이 지루해진다)
- 위 「이 값을 바꾸지 않는다」 표의 숫자를 바꾸지 않는다.
  바꾸면 「요령」 세 줄이 거짓이 된다
- **바깥 CSS 를 새로 쓰지 않는다.** `src/styles/game.css` 에 이미 다 있다
- 게임 안에 `LANGS` `pickLang()` `apply()` 를 만들지 않는다
- 다른 게임 파일을 건드리지 않는다 (`design/README.md` 한 줄 넣는 것만 예외)
- 게임 안에 검은 고양이를 넣지 않는다

## 8. 확인 차례

### 8-1. 빌드

```bash
npm run build
```

쪽이 **102 → 108** 로 는다 (게임 하나 × 나라말 여섯).

### 8-2. 헤드리스로 재서 알려줄 것

**「요령」 세 줄이 참인지 재는 것이 목적이다.**

1. **요령 1** — 봇 둘을 각 200판 돌린다.
   (가) 공만 쫓는 봇 · (나) 공이 하나뿐일 때도 아이템을 쫓는 봇.
   **(가)가 더 멀리 가야 한다.** 도달한 판과 점수를 둘 다 찍는다
2. **요령 2** — 막대 접점이 `-1.0 / -0.5 / 0 / +0.5 / +1.0` 일 때
   튕겨 나가는 각을 표로 찍는다. **끝일수록 옆으로 커야 한다**
3. **요령 3** — `narrow` 가 걸린 상태에서 `wide` 를 받으면
   **그 자리에서 풀리는지** 확인한다. `fast` ↔ `slow` 도 같이
4. **막판** — 벽돌 3개만 남긴 상태로 200판 돌려
   **90% 이상이 30초 안에 끝나는지**. 안 되면 5번 규칙의 숫자를 조정하고, 조정한 값을 알려준다
5. **아이템 확률** — 100판 돌려 벽돌 하나당 아이템이 나온 비율.
   **14% 안팎**이어야 한다. 좋은 것과 나쁜 것 비율도 찍는다 (7:3 안팎)
6. **판 12개** — 판마다 벽돌 개수와 단단한 벽돌 비율을 표로

### 8-3. 대표 그림

```bash
node scripts/make-og.mjs
```

- `public/og/home-ko.png` — **게임이 11개가 됐다.** 잘리지 않고 다 보이는지

### 8-4. 차례표

`design/new-game-checklist.md` 의 **7번 목록을 전부** 짚는다.
특히 —

- 나라말 여섯 개를 다 열어본다
- 일본말·중국말 제목이 두 줄로 안 넘치는지
- 아이템 이름이 `.legend` 칸 밖으로 안 넘치는지 (프랑스말이 제일 길다)
- 폰(390px)에서 막대가 손가락에 안 가리는지
- **받는 링크를 세어 본다** — 열한 개가 되면 `related()` 셈이 바뀐다.
  링크를 하나도 못 받는 게임이 없어야 한다
